# Verifiable Autonomy Layer & ledger-invariant

[![Weights: CC BY-NC-SA 4.0](https://img.shields.io/badge/weights-CC%20BY--NC--SA%204.0-lightgrey.svg)](https://huggingface.co/ayokalabs/ledger-invariant-10m)

An execution harness that checks an agent's proposed action against declared invariants before it is applied, and a small learned verifier trained to approximate that check from traces alone.

**What is established, as of 12 October 2026.** A 12.25M-parameter transformer, trained only on 50,000 synthetic traces and never shown the rules, approximates a rule oracle at 87% on a held-out set. It solves the SCADA domain completely and fails on seven-digit treasury arithmetic, mostly near thresholds. The benchmark carries a leakage probe; a first run that reached 100% through action-name leakage was discarded. Every error is published with its inputs. Code, weights and model card are reproducible at the commit.

**What is not claimed.** The model does not beat the rules: the exact rule oracle scores 100% on this benchmark by construction. It offers no mathematical guarantee, its scores are not calibrated, and it has only been tested on synthetic data in two domains.

## Limitations

- **Synthetic data only.** Both domains are generated by a rule oracle. No real logs, no out-of-domain test set.
- **Sensitive to number formatting.** Training amounts are random with two decimals; the model has never seen round amounts. At equal margin and state, `amount:4500000.0` is misclassified while `amount:4512338.27` is correct.
- **Unbalanced ledger entries are the weakest rule**: 70% recall on violations.
- **Scores are not calibrated.** The model has answered `ALLOW` with score 0.99 on a case that was `BLOCK`.
- **Two classes.** Post-action divergence (`ROLLBACK`) is excluded from v0.1 because its signal was not observable in the input. It returns in v0.2 through an explicit checksum field.

## Reproduce

```bash
git clone https://github.com/ayokocrj/verifiable-execution-harness.git
cd verifiable-execution-harness
pip install torch
python -m unittest discover -s tests                       # 27 tests

python scripts/generate_dataset.py --samples 50000 --out data/synthetic_traces_50k.jsonl --seed 42
python scripts/generate_dataset.py --samples 500 --out data/traces_test_v01.jsonl --seed 2026
python scripts/train.py --model_size 10m --num_classes 2 --epochs 10 --batch_size 64 --lr 3e-4   # T4, under 10 minutes
python scripts/benchmark_models.py --samples 1000 --model_path checkpoints/ledger_invariant_10m_final.pt
python scripts/error_analysis.py --model_path checkpoints/ledger_invariant_10m_final.pt --dataset data/traces_test_v01.jsonl
```

Training: 45,000 train / 5,000 validation, AdamW lr 3e-4, weight decay 0.01, gradient clipping 1.0, seed 42. Loss 0.458 to 0.280 over 10 epochs, validation accuracy 74.1% to 87.5%. Without a GPU, `scripts/benchmark_models.py` runs the rule oracle and labels the row accordingly.

## How the pieces fit

```
Agent proposes an action (tool call)
        |
        v
Verifiable Autonomy Layer (harness/)
  1. clone the in-memory state into a sandbox
  2. encode (state, action, criteria) with the InvariantTokenizer
  3. ask the verifier: rule oracle (synthetic_data/rules.py) or learned model (models/)
        |
   ALLOW: apply the mutation        BLOCK: refuse it
        |
   if an invariant fails after applying: in-memory rollback (0.02 to 0.05 ms per action in run_harness.py)
        |
        v
Append-only ledger: Hash_N = SHA256(payload + Hash_{N-1}); tampering is detected by tests/test_harness.py
```

The harness is independent of the verifier. The learned model is one verifier among others; the rule oracle is the reference.

## Repository structure

```
harness/                 sandbox, invariants, rollback, SHA-256 ledger, agent hook adapter
models/                  tokenizer, LedgerInvariantDecisionTransformer, DecisionEngine
synthetic_data/          rules.py (single oracle shared with the generator), generator.py
benchmarks/              eval_suite.py (baselines incl. leakage probe), domain benchmarks
scripts/                 generate_dataset.py, train.py, benchmark_models.py, error_analysis.py
tests/                   27 tests: harness, tokenizer determinism, anti-leakage, oracle congruence
run_harness.py           in-memory demonstration of the harness
```

## Demonstration run (harness, in memory)

Output of `python run_harness.py` on 12 October 2026 (rollback and tamper detection are also asserted by `tests/test_harness.py`):

- 9 actions across the SCADA and treasury scenarios, 4 injected breaches, 4 caught, 4 rollbacks, 0 state drift.
- Machine-side invariant check: 0.02 to 0.05 ms per action, 0.23 ms average including ledger sealing.
- Ledger audit: 9 blocks verified, 0 discrepancies; a retroactive modification of a committed record fails the audit.

## Roadmap

- **v0.1, 12 October 2026 (shipped):** 10M, traces only, binary gatekeeper.
- **v0.2, target 22 November 2026:** 35M, short pretraining on FineWeb-Edu plus traces, three classes with `ROLLBACK`, round and mixed number formats in the generator, a domain held out from training, two sizes for one scaling point.
